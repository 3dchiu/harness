# 生涯定位 App — 架構地圖 v1

> 本文件收斂自一次產品設計討論，整合：演講 PDF《16 卡點診斷與行動建議》的理論、
> 既有網站測驗的程式邏輯、以及團隊已製作的 7 個小工具。
> 目的：作為可拿去與工程／設計溝通、或自行驗證的單頁藍圖。

## 0. 一句話定位

> 一款**診斷型**生涯成長 App：用 **S–W 雙軸**找出你卡在哪，給你**可執行的行動骨架**，
> 並透過**持續回補**讓你的自我認知與市場認知一起長大。

跟 GrowMe 那類「內容圖書館＋每日書摘」不同——我們的核心是**診斷與轉變**，
護城河是「卡點判斷邏輯」，不是內容數量。

## 1. 理論底座（以 PDF 為準）

**知己知世 · S–W 座標軸**
- **S 軸｜自我認知**（縱軸）：方向感、能力優勢、價值觀的清晰度
- **W 軸｜市場認知**（橫軸）：對外部世界、選項、路徑、市場回應的掌握度

**四象限**

| 象限 | S × W | 核心本質 |
|------|-------|----------|
| 探索型 | S低 × W低 | 沒有選項，不知道世界有什麼 |
| 突破型 | S高 × W低 | 有方向但進不去市場 |
| 決策型 | S低 × W高 | 有選項但選不出來 |
| 升級型 | S高 × W高 | 已在軌道但上不去 |

**16 卡點分類學（4 / 4 / 3 / 5，以 PDF 為準）**

| 象限 | 卡點 |
|------|------|
| 探索型 | A.視野太窄　B.感知未建立　C.條件過嚴　D.認同困境 |
| 突破型 | A.能力落差　B.敘事落差　C.入口錯誤　D.市場結構困難 |
| 決策型 | A.缺乏標準　B.風險恐懼　C.資訊迴避 |
| 升級型 | A.責任不足　B.能力缺口　C.系統天花板　D.信任缺口　E.位置錯誤 |

**診斷信號（冰山之下）**
- **S 穩定度**：說了之後變不變？（profile 完成度＝穩定度指標之一）
- **W 驗證度**：市場回不回報？（閱讀／投遞／面試回應累積）

## 3. 雙迴圈架構（產品的引擎）

```
Loop A〔縱深 · 短期〕   卡點 ──→ 行動骨架 ──→ 解決當下這一關
                            │
                            ↓ 行動產生的資料回補
Loop B〔背景 · 長期〕   S軸 profile  +  W軸 市場資料庫
                       （持續養，重測時看到成長）
```

- **Loop A**：解決「現在卡住」的問題，是使用者上門的理由。
- **Loop B**：把 S/W 從「一次性測驗分數」變成「會長大的個人檔案」。
  - 重測時 S/W 上升、象限位移、卡點改變 → **可見的成長 = 續訂理由**。
  - **這就是訂閱制的引擎**（解決了「療程解完就走」的留存難題）。

**雙軸互相校正（重要原則）**
診斷不是單向的——**一個軸的真實表現，會回頭修正另一個軸的自評**。
- 例：突破型（自評 S 高）若投遞勝率持續偏低（W 的真實回報差），
  代表「S 高」被高估了，特別是**專業這一塊**——此時應**路由回 S 軸做「專業梳理任務」**
  （把專業拆成可舉證的硬技能/成果清單），而不是繼續改履歷。
- 含義：行動結果（W）是 S 自評的測謊器；S 盤點又讓下一次 W 評估更準。
  這讓雙迴圈不只是「並行」，而是「互相回補、越用越準」。

## 4. 三層交付 × 對應商業模式

| 層 | 內容 | 規模化 | 商業定位 |
|----|------|--------|----------|
| **Layer 1｜規則化** | 診斷引擎 ＋ 解法庫（pathLib）＋ 行動骨架模板 | 零邊際成本 | 免費／引流 |
| **Layer 2｜AI 客製** | 用 intake＋診斷結果填入骨架變數、反思引導、履歷客製 | 低成本 | **訂閱核心** |
| **Layer 3｜真人** | 複雜條件下的判斷取捨、陪伴督促、計畫撞現實後的調整 | 不可規模化 | 高價諮詢 |

**邊界原則**：刀不切在「方向 vs 行動」，而是切在「**通用骨架 vs 個人判斷**」。
- App 做到：方向 ＋ 通用行動骨架 ＋ 輕量 AI 客製
- 真人保留：深度個人化校準 ＋ 陪伴調適

**防罐頭三機制**（使用者最在意）：
1. 個人化變數（AI 依 intake／診斷填空）
2. 每日反思提問（逼使用者產出自己的內容）
3. 診斷結果順移（把測驗答案帶進行動）
> 骨架人人一樣是對的；不罐頭靠「血肉」，不靠改骨架。

## 5. 行動骨架標準格式（第二層解剖）

每一條卡點 → 選定方向（來自 pathLib）→ 7 天骨架：

```
・目標：這 7 天的最小可見成果
・每日微任務（10–20 分鐘、可勾選）
・每日反思提問          ← 防罐頭①
・個人化變數 {…}        ← 防罐頭②（AI 填）
・完成信號              ← 對應 PDF 診斷信號（S穩定度／W驗證度）
・（選配）做不到時的最小替代版
```

**四象限樣板（各取一卡點，已含修正）**

- **探索型 A·視野太窄**　方向：用對話換一張地圖
  D1 AI 用固定架構說明 3 個好奇職業「實際在做什麼」→ D2 AI 補 2 個鄰近職業 →
  D3 排序興趣度（回補 S 軸）→ D4 才搜尋真實的人 → D5 寫邀約 → D6 送出/看公開訪談 → D7 畫一頁地圖
  （修正重點：AI 先行、真人後置，避開「找真人很難」的 MVP 殺手）

- **突破型 B·敘事落差**　方向：對應具體職缺改寫履歷
  選定目標職缺 → 用**職缺勝率工具**分析落差 → 依職缺用語改寫經驗敘事 → 找懂市場的人驗證 → 放進履歷/開場
  （核心引擎＝既有職缺勝率工具）

- **決策型 B·風險恐懼**　方向：拆解選錯的真實代價
  列出多個選項 → 使用者挑選並**排序重要性** → 各寫最壞情況與可逆性 → 找過來人問實際後果 → 設低代價試水版

- **升級型 A·責任不足**　方向：主動爭取一個小決策權
  盤點「只執行沒決定」的環節 → 選一個 → 設計 30 秒提案 → 開口要 → 做決定並記錄 → 主動回報讓決定被看見 → 復盤

## 6. 工具掛載地圖（既有資產 → 槽位）

> 好消息：診斷邏輯有了、解法庫有了、血肉工具也有 7 個。
> App 的工作是**編排**，不是從零造內容。

| 既有工具 | 掛載槽位 | 角色 |
|----------|----------|------|
| 價值觀排序工具 | S 軸回補／探索型 | 釐清「想要什麼」 |
| 打分數 ＋ 加一分行動 | S 軸日常微行動 | Loop B 每日鉤子 |
| 興趣盤點（持續中／曾中斷）、專業盤點（學歷／經歷） | S 軸 profile | 個人化變數來源 |
| 產業新聞推薦 ＋ 讀完打勾 | W 軸回補資料庫 | Loop B 每週鉤子 |
| 職缺勝率工具 | 突破型 B 骨架引擎 | Layer 2 客製履歷核心 |
| 離職狀態診斷工具 | 入口分流／情境模組 | 判斷「現在該不該動」 |
| 薪資談判力診斷器 | 升級型／offer 階段 | 談判前準備 |

## 8. 商業模式分層（先療程、後訂閱）

| 階段 | 形態 | 目的 |
|------|------|------|
| 階段一·驗證 | 一次性付費療程（一條最強卡點路徑，14 或 30 天） | 證明有人願付費、完成率夠高 |
| 階段二·養引擎 | 擴充解法庫＋導入 Loop B 回補＋AI 客製 | 累積留存/回訪數據 |
| 階段三·疊訂閱 | 月/季/年訂閱（Loop B 持續價值＋重測成長＋真人層） | 把一次性買家轉續訂 |
